# Design Queue — Schema Proposals (CSA-N)

**Status**: Living — updated as design iterates
**Purpose**: Track all schema design proposals (CSA-1 through CSA-47) with design rationale, evaluated on correctness only — phasing lives in [scoping.md](scoping.md).
**Audience**: Engineers evaluating a proposal's design rationale; DRY/correctness review; product narrative fit.
**Companion to**: [decisions.md](decisions.md) (locked proposals graduate here), [design-lessons.md](design-lessons.md) (patterns that informed these proposals), [table-designs.md](table-designs.md) (DDL for designed tables)

## How to read this file

- Scan the **ID** column (CSA-1 through CSA-47) to find a specific proposal
- **Design status** column shows current state: "Designed", "Open question", or "Designed with trigger"
- Locked proposals reference their decision ID (e.g., D8, D14) — follow to [decisions.md](decisions.md) for the verdict
- Phasing (MVP vs post-MVP, cost, triggers) is deliberately absent — that lives in [scoping.md](scoping.md)

## Status model

- **Open question** — design not yet decided
- **Designed** — design locked at pattern level, awaiting scoping pass

Phasing (`MVP vs post-MVP`, cost estimates, triggers) is deliberately NOT in this file —
it biases per-item decisions. Scoping happens once, across the full picture, in `scoping.md`.
