## Evidence

### Final rule boundary

- CMS-0057-F is a final rule effective April 8, 2024.
- Impacted payers are Medicare Advantage organizations; state Medicaid and CHIP
  fee-for-service programs; Medicaid managed-care plans; CHIP managed-care
  entities; and Qualified Health Plan issuers on Federally Facilitated
  Exchanges.
- The rule does not directly apply these requirements to Medicare fee-for-service.
  It also excludes drugs from its prior-authorization API and process policies.
- Operational duties begin in 2026. API duties apply primarily in 2027, with
  program-specific dates for managed care and QHP plan years.

### Operational and API duties

- Except for FFE QHP issuers, payers must decide expedited requests within 72
  hours and standard requests within seven calendar days.
- A decision response must state approval and duration, denial and a specific
  reason, or request additional supporting information.
- The rule does not require real-time adjudication.
- Calendar-year 2025 prior-authorization metrics had to be published by March
  31, 2026. Metrics exclude drugs and include approval, denial, appeal,
  extension, and elapsed-time measures.
- Payers must implement and maintain a Prior Authorization API through which a
  provider can discover whether authorization is required, query documentation
  requirements, submit a request, and receive its disposition.

### EHR and standards boundary

- The Electronic Prior Authorization measure begins in the CY 2027 performance
  period/CY 2029 MIPS payment year and the CY 2027 EHR reporting period.
- The final measure is a yes/no attestation or applicable exclusion. The exact
  detailed CEHRT configuration was outside the bounded returned rule extract.
- FHIR R4.0.1 is among the required API standards. CMS-0057-F strongly
  recommends supplementary implementation guides; it does not make them
  mandatory in this final rule.
- CMS separately grants HIPAA enforcement discretion when a covered entity omits
  X12 278 from the rule-described FHIR prior-authorization process. That is
  guidance, not an amendment or repeal of the HIPAA transaction standard.

## Notes

The rule creates a mixed environment. It regulates only specified payer classes,
excludes drugs and Medicare FFS, allows non-real-time clinical review, and does
not make its process duties depend on API submission. Provider-side software
must therefore coexist with FHIR APIs and legacy channels rather than assume a
single cutover.

The CMS FAQ initially describes deadlines for impacted payers generally, then
expressly excludes FFE QHP issuers. GovInfo resolves the ambiguity in favor of
the specific QHP exception.
