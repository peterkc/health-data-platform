# Decisions — Authoritative Log

**Status**: Living — append as new decisions lock
**Purpose**: Single source of truth for locked schema decisions, each with a pointer to the detailed rationale in the appropriate design file.
**Audience**: Engineers checking "what did we decide?" before implementing; reviewers verifying design consistency.
**Companion to**: [design-queue.md](design-queue.md) (proposals before they lock), [open-questions.md](open-questions.md) (resolved questions that became decisions), [scoping.md](scoping.md) (phasing decisions — what ships when)

## How to read this file

- Scan the **ID** column (D1-D28) to find a specific decision by number
- **Locked answer** column gives the one-line verdict; **Detail** column links to the full rationale
- Phasing decisions live in [scoping.md](scoping.md), not here
- Design proposals still under review live in [design-queue.md](design-queue.md)

| D19 | How are trust-level conflicts resolved when two sources at the same trust level disagree?        | **Silver keeps all rows; gold-tier reconciles via `ref_reconciliation_rules`**. New `ref_reconciliation_rules` table — `(metric_code, metric_system)` key + `priority_chain JSON` (ordered list of preferred source_system values) + `fallback_strategy` enum (most_recent / weighted_avg / user_preference). | D20 | How does consent on derived data work (embeddings / summaries / scores)?                         | **Derived data inherits source consent through PDP transitive evaluation** — pattern, not a table. PDP (D9) evaluates derived-data reads by dereferencing source rows — if the requestor cannot read the source, they cannot read the derivation. | D21 | How does Health OS return errors for access-denied reads?                                        | **Audience-split — NotFound (non-patient-facing) vs PermissionDenied (patient-facing)**. Classification: hybrid — (`actor_id == target_patient_id`) OR (`agent_session.on_behalf_of == target_patient_id`) OR (`active_grant.purpose == 'patient_delegate'`). Extends `access_grants.purpose` enum with `patient_delegate`. Every denial writes `access_log` regardless of response class (P1 transparency + P4 audit). Modeled on Microsoft OBO (RFC 8693), Azure RBAC, Google Cloud IAM, Kubernetes RBAC. Resolves OQ-4.                                                                                                                                                                                                                                                                                                                                                                                                            | [data-plane.md](data-plane.md)                                                               |
| D22 | What evaluates authorization decisions at the Repository boundary?                               | **OpenFGA on Postgres as PDP + in-process LRU Tier 1 cache**. Static policies (`policy_rules` per D9 PAP) → OpenFGA type definitions; dynamic grants (`access_grants` per D10) → OpenFGA tuples; D20 transitive consent → computed usersets. Tier 2 shared cache (Valkey — BSD, Linux Foundation) deferred until measured need (in-process hit rate < 70% OR p99 exceeds budget). Add OPA sidecar if static policies exceed OpenFGA type-system expressiveness (~20+ types). All components Apache 2 / BSD, CNCF-portfolio, self-hosted on Health OS's infra (P4); zero new BAA relationships. Resolves OQ-5.                                                                                                                                                                                                                                                                                                                         | [data-plane.md](data-plane.md)                                                               |
| D23 | What does Health OS do when PDP (OpenFGA) is unavailable?                                        | **Graceful degradation with signaling** — Tier 1 LRU hits continue during outage (TTL-bounded stale-permit, default 60s); cache miss fails-closed (503 Service Unavailable). Every response envelope carries `degraded_mode` + `decision_source` in `metadata.access_decision`. Circuit breaker wraps OpenFGA calls. 42 CFR Part 2 records opt to strict fail-closed (sensitive-category override). Phased: MVP = graceful degradation + circuit breaker; post-MVP adds Postgres RLS coarse fallback (belt-and-suspenders) + break-glass emergency override (separate workflow with typed justification + 48hr review + patient notification). Modeled on Kubernetes RBAC kubelet TTL continuity, Zanzibar zookie staleness, SpiceDB consistency levels, Microsoft Entra break-glass. Balances HIPAA §164.306(a) availability requirement + 21C Cures info-blocking rule against P1 privacy. Resolves OQ-6.                           | [data-plane.md](data-plane.md)                                                               |
| D24 | How is the in-process LRU PDP cache sized, keyed, and invalidated?                               | **Fixed entry count (10k default per worker, configurable via env var) + uniform 60s TTL + action-aware key `(actor_id, action, resource_type, resource_id, purpose)` + cache both permits and denies + TTL-only eviction with bulk flush on rare admin events (HOM tree change, bulk grant migration)**. Consistency tokens (OpenFGA-native, Zanzibar zookie pattern) phased post-MVP for write-path cache bypass. Measure-first posture: bump to 50k before Tier 2; hit-rate + memory metrics emitted. Resolves OQ-7.                                                                                                                                                                                                                                                                                                                                                                                                               | [data-plane.md](data-plane.md)                                                               |
| D25 | How does batch PDP evaluation aggregate partial results?                                         | **Hybrid per-operation** — collection reads use partial-permit (return only accessible records, omit denied); single-resource reads use binary permit/deny with D21 audience-split error shape. Patient-facing lists include `filtered_count` in response metadata for HIPAA §164.524 transparency. Aligns with FHIR Bundle/search semantics, Google Drive, AWS S3 ListObjects, Cedar `is_authorized_batch`. Resolves OQ-8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | [data-plane.md](data-plane.md)                                                               |
| D26 | Which FHIR version ships as the first ClinicalRecord format adapter?                             | **FHIR R4 first (STU 4.0.1), R5 additive later**. Per ADR-2002. 95%+ US EHR interop is R4; R5 adoption \<5% in production. Adapter interface is version-agnostic (`ClinicalRecord → format(version)`), so R5 slots in without changing read/write path. R5 added when a concrete partner requires it (measure-first). Resolves OQ-9.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | [data-plane.md](data-plane.md)                                                               |
| D27 | How is the ClinicalRecord envelope versioned?                                                    | **Envelope field `metadata.envelope_version: 1`** in every response. Transport-agnostic (works for HTTP, async events, internal callers). Additive fields = no version bump (Postel's Law); breaking shape changes bump integer. Each format adapter declares `min_envelope_version` / `max_envelope_version` at registration. HTTP layer may mirror in `X-Envelope-Version` header for convenience; envelope field is authoritative. Resolves OQ-10.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | [data-plane.md](data-plane.md)                                                               |
| D28 | Is the Health OS M3 substrate PostgreSQL or Dolt?                                                | **PostgreSQL 18 (18.3)** — supersedes ADR-1001's Dolt substrate (via ADR-1010). Primitives: `uuidv7()` PKs (sortable v7 UUIDs), temporal PK/FK with `WITHOUT OVERLAPS`, `RETURNING OLD/NEW` for audit triggers, pgvector for embeddings (D5), AIO (async I/O), OAuth 2.0 verifier. Enables D7 split co-location, D22 OpenFGA-on-Postgres PDP (single-engine audit trail, no cross-engine reconciliation), and pgvector transactional writes per ADR-1011. Locked 2026-04-16 (ADR-1010 flipped Proposed → Accepted).                                                                                                                                                                                                                                                                                                                                                                                                                   | [database-substrate.md](database-substrate.md)                                               |

**D7 rationale**: Data-type catalog composes 15 public schemas; FHIR / OMOP / openEHR / Fasten all separate condition-like entities from observations; only i2b2 unifies (different workload — federated analytics, not application-first). Single-table forces extensions JSON to carry state machines (condition.clinical_status, medication.status, allergy.criticality) — semantic loss + query degradation. Split preserves FHIR semantic richness at storage layer and makes every downstream CSA (CSA-14 through CSA-35) a clean table addition rather than a fight with `record_type` enum. See [data-type-catalog.md](data-type-catalog.md) and [platform-malleability.md](platform-malleability.md) for evidence.

## Framing decisions

| Topic                                 | Decision                                                                                                                    | Why                                                                                                     |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Scope lens                            | **POC → durable product with minimal refactor** (not "throwaway demo")                                                                  | Schema must serve the full product trajectory, not just a demo. See [README.md Context line](README.md) |
| Health OS framing                     | Health OS aggregates from N sources (wearables, labs, EHR, pharmacy, imaging, genomics, manual) — schema is source-agnostic | Rationale: source plurality is architectural; identity must be source-agnostic                          |
